# News engine v2: shadow collection

This is a shadow implementation, not the production cutover. Existing `/api/daily`, article IDs, debates and user records remain on the current engine. `NEWS_ENGINE_V2=shadow` and `NEWS_INGEST_SECRET` enable the protected `POST /api/internal/ingest` and `GET /api/internal/ingest/status` endpoints. Requests must carry `Authorization: Bearer <secret>`. Never put that secret in client code or logs. Both endpoints remain unavailable when either setting is absent. Apply the Drizzle migration before enabling shadow collection.

The registry contains feeds that returned RSS during local verification. Collection stores title and URL metadata only, not descriptions or article bodies. `domain_matched` means only that the URL uses an allowed publisher domain; it is not proof of access rights, article content, or independent reporting. Google News links remain `metadata_only` and are not treated as verified original URLs. Publisher groups prevent multiple feeds from the same organization being counted as multiple publishers. Usage rights, including public redistribution and AI processing, must be checked separately for each provider before production use.

Shadow runs store per-feed success and failure, prevent concurrent runs with a lock and deduplicate canonical URLs. A separately invoked Patch 2 clustering run records decisions and memberships in isolated, versioned shadow tables. It searches bounded candidates within 48 hours and uses title, limited actor/action/topic signals and contradictions. Explicit conflicts are rejected; ambiguous matches are provisional; confirmed matches require exact normalized titles or a strict structured match. Each addition is compared with the representative and checked against member conflicts; competing confirmed clusters cannot be bridged. This conservative matcher misses many related articles and its labels are not human-verified truth. A matching headline or multiple publishers does not establish factual independence or validate a claim. The queue helper expresses source coverage only; it does not assess importance, debate suitability, evidence quality, or editorial approval.

`POST /api/internal/cluster` and `GET /api/internal/cluster/status` use the same shadow-mode and bearer-secret guard. `POST /api/internal/news-cycle` runs collection then clustering under a separate lock, preserving existing complete runs if the next run fails. It does not publish. Clustering reads existing candidates only; it does not call feeds or a model. An optional injected adjudicator can receive only titles, publishers and timestamps for bounded provisional reviews. Its confirmation cannot cause automatic merging, and the exposed endpoint does not enable it. See the [initial review](benchmarks/shadow-clustering-2026-10-30.md) and [Patch 2.5 comparison](benchmarks/patch-2-5-2026-10-30.md); neither is a human-labelled accuracy evaluation.

`node scripts/evaluate-clusters.mjs <dataset.json> [k]` accepts `{candidates,labels}`. Candidate fields are `id`, `title`, `publisher`, `publisherGroup`, `publishedAt`; labels have `a`, `b`, `label` (`same` or `different`), `reviewed: true` and `reviewer`. Only explicitly reviewed labels count. Missing denominators produce `null`, never a fabricated percentage. Recall@K covers retained representative comparisons only; labelled non-representative pairs count as misses, and K is limited to 1–8. This is not full-corpus pairwise retrieval recall. Include blind, independent human judgements, including omitted pairs, before using the metrics for a release decision.

## Shadow issue debates

After migrations 0003–0005, `POST /api/internal/issues/<run-id>/<issue-id>/debate` generates a shadow debate and `GET` reads it using the existing article response shape. Both require the shadow flag and bearer secret; neither changes `articles` or the public feed. A completed shadow cluster must contain 2–4 different publisher groups with candidate-specific grants for the exact URL, fetch, AI processing, display and documented independence. No grants are supplied by default. A manually recorded independence attestation is required; group counts do not prove independent reporting. Known wire attribution and highly similar original text are rejected, but this does not detect every syndicated article. Redirects beyond the exact granted URL are rejected.

The generation pass uses the existing shared daily AI budget; a second, separately budgeted Gemini pass assesses the six turn citations and the overall question, context and summary. Each `fact` must be an exact excerpt of its cited paragraph and every digit in a turn must occur in that paragraph. All six citations must resolve, at least two source IDs must be used, all verifier verdicts must be `supported`, and uncertain or malformed results are rejected. The model verifier is probabilistic and does not establish legal permission, entailment, factual truth, editorial balance or independence. A successful result is cached only in `shadow_debates`; grant expiry or revocation blocks cache retrieval. Failed calls preserve any prior stored result and count against the limit. `ISSUE_EDITORIAL_VERSION=5` is scoped to this new path; the legacy single-source engine remains version 4 so old output is not mislabeled as multi-source.

`node scripts/test-d1-issue.mjs` exercises the entire internal issue path against Miniflare D1 using synthetic articles and mocked Gemini. It is not a live-source or real-model test.

The public legacy v4 API blocks new generation and rewriting. Existing cached debates remain stored but public responses hide them unless every cited URL has a current per-URL grant allowing AI use and display. Feed descriptions are not displayed. The extractor also refuses an explicit `AI 학습 및 활용 금지` notice; absence of a notice is not permission. The legacy direct helper is retained for isolated tests and is not exposed by the public generation endpoint. The existing title/link feed is still legacy and its redistribution rights need review.

Before production cutover, independently evaluate event matching against human-labelled examples and validate source permission records, source independence and semantic verification against a human-reviewed evidence set. Complete ambiguous-pair review, safe original URL resolution, issue-level editorial review and ranking, publication with stable issue/article IDs, failure recovery, sources UI, and a scheduler. No automatic ingestion schedule is installed. In particular, setting `NEWS_ENGINE_V2=shadow` does not enable v2 publication. Do not advertise shadow groups as verified or use them to replace the current feed.

The publisher's own terms should be reviewed for the actual intended use. For example, [한겨레의 저작권 안내](https://oauth.hani.co.kr/help/rules/mypage_help_copyright.html?type=digital_use_rule) describes restrictions on RSS redistribution. An RSS endpoint returning HTTP 200 does not establish authorization to reuse article text or transmit it to a model.
